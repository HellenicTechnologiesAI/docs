## What this is

Cursor can talk to iubenda over MCP (`https://mcp-server.iubenda.com/mcp`) and drive the web GTM container in the browser. The personal skill `iubenda-gtm` loads when you mention iubenda, cookie banner, CMP, Consent Mode, or `ht_consent_ready`.

It does **not** provision Stape, a Cloudflare Worker, or CAPI. That is Scenario A/B.

Playbook still wins over this page, GTM defaults, Stape UI, and plugins.

## One-time Cursor setup (each teammate)

Do this once per person. Then Connect iubenda with **your** iubenda login.

1. Open `~/.cursor/mcp.json` and add:

```json
"iubenda": {
  "url": "https://mcp-server.iubenda.com/mcp"
}
```

2. **Cursor Settings → MCP → iubenda → Connect**. Sign in to iubenda and click **Allow access**.
3. In a new chat, ask: `List my iubenda sites.` If that fails, disconnect and Connect again.
4. **Skill (optional but faster):** copy `skills/iubenda-gtm/` (the `SKILL.md` + `ht-gtm-consent.md` from a machine that already has it) into your user Agent Store. If you skip this, paste a prompt from this page instead — the playbook still applies.

<Note>
  The skill lives in the user Agent Store (`skills/iubenda-gtm/`), not in `ht-<customer>` repos. Each teammate installs MCP + OAuth themselves. Do not commit iubenda tokens.
</Note>

## When to use which prompt

| Job | Prompt | Do not use |
| --- | --- | --- |
| New banner + policy on a customer web GTM | Setup | Full Scenario B unless they also need Stape |

| Check before an SST job or a client call | Audit | Any GTM publish |
| Meta / TikTok / LinkedIn fire on All Pages | Fix | Adding more pixels |
| Reject still sends CAPI / Ads | Fix | Pausing the web pixel to go server-only |

| No Stape yet and you need sGTM | [Scenario B](/kb/web-analytics/cursor-prompt-new-customer) | This page alone |

## Team split

- **PM / Cursor:** iubenda MCP (site, policy, banner), GTM template, `ht_consent_ready`, pixel triggers, sGTM consent checks.
- **Web-dev, one-time:** remove theme/plugin CMP and extra `gtm.js` / plugin pixels. Paste Stape Custom Loader only if that ticket already exists. They do **not** paste iubenda.
- Never ask developers for pixels, conversion tags, or iubenda snippets.

## Prompt — audit / check

No GTM edits. No iubenda writes except `list_*` / `get_*`.

```text
You are the tracking engineer for Hellenic Technologies.

This job is AUDIT ONLY for iubenda + Consent Mode Advanced v2 on {{website_url}}.
Do not edit GTM, iubenda, Stape, DNS, or the website.

Read first:
https://ht-intra.mintlify.site/kb/web-analytics/server-side-tracking
https://ht-intra.mintlify.site/kb/web-analytics/cursor-iubenda-gtm

Check and report:
- Where the CMP lives (GTM template vs theme vs plugin vs none vs second CMP).
- What fires before accept (gtm.js, fbq, ttq, lintrk, gtag G-/AW-, CAPI).
- Consent Initialization tag present? emitGtmEvents? defaults denied?
- purpose 5 / ads trio → one ht_consent_ready with event_id? Or pixels on All Pages?
- sGTM adStorageConsent required? Any marketing hit on G100?
- Match cookies (_ht_vid, _fbp, _fbc) before purpose 5?
- Second web GTM or googletagmanager.com/gtm.js beside Custom Loader?

Web GTM: {{gtm_web_id_or_unknown}}
sGTM / sgtm host: {{id_or_unknown}}

OUTPUT
1) Where CMP lives
2) What fires before accept
3) Severity list (critical / major / minor) with the specific fix
4) Whether this is consent-only or needs Scenario A/B
Stop. Do not spec implementation unless I ask.
```

```text

Symptoms: {{theme_cmp | pixels_on_all_pages | capi_on_denied | no_ht_consent_ready | other}}

HARD RULES
- iubenda in GTM Community Gallery, Consent Initialization – All Pages.
- Move theme/plugin CMP out via one web-dev ticket after GTM iubenda is ready.
- Move Meta / TikTok / LinkedIn base pixels onto ht_consent_ready.
- Stop match cookies before purpose 5.
- sGTM marketing tags: adStorageConsent required.
- Named publish only after I approve the patch list.
- ht-{{customer_slug}} repo. No credentials in git.

ORDER: audit → patch list → wait → patch → named GTM publish → QA gates.
```

## QA gates

| State | Expect |
| --- | --- |
| Fresh reject | Ads + analytics denied. No Meta PageView / TikTok / Insight. No marketing CAPI. |
| Analytics only | GA4 yes. Ads/Meta no. |
| Ads accept | One `ht_consent_ready`. Base pixels on **that** landing URL (UTMs / click IDs still there). |
| Refresh after accept | Banner does not flash. |
| Loader | iubenda from GTM, not theme. No second CMP. No second `gtm.js`. |

GTM Preview on the published version. Do not leave work only in Default.
