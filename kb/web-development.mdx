The Web Development team builds websites and web applications for clients across three primary package tiers (Falcon, Lynx, Mammoth) plus custom Agentic Websites. This page serves as the internal reference for scoping projects, understanding our technology stack, assigning team roles, and following delivery standards consistently across every engagement.

## Technology Stack

Our core stack covers the tools and platforms used across the majority of web projects:

- **WordPress** — primary CMS for Falcon, Lynx, and most Mammoth builds
- **WooCommerce** — eCommerce layer on top of WordPress
- **React / Next.js** — used for custom web applications and Agentic Websites
- **Figma** — all design handoffs originate in Figma before entering development

## Service Types & Typical Timelines

We deliver web projects across four package types. Use the table below when scoping timelines with clients and PMs:

| Package | Description | Typical Timeline |
|---|---|---|
| Falcon | Commercial template-based sites | 2–4 weeks |
| Lynx | HT signature template sites | 3–5 weeks |
| Mammoth | Fully custom design & development | 6–12 weeks |
| Agentic Websites | AI-powered sites with embedded agents | 4–8 weeks |

For a detailed comparison of Falcon, Lynx, and Mammoth, see the [Website Packages](/kb/website-packages) page. For a full breakdown of Agentic Websites, see the [Agentic Websites](/kb/agentic-websites) page.

## Standard Web Project Delivery Flow

Every web project — regardless of package type — follows this delivery flow. Deviations require sign-off from the Project Manager.

<Steps>
  <Step title="Discovery & Scoping Call">
    Hold a structured call with the client to capture requirements, technical constraints, content needs, and business objectives. Document outputs in the project brief.
  </Step>
  <Step title="Proposal and Sign-Off">
    Prepare and send the project proposal including scope, timeline, deliverables, and pricing. Work does not begin until the client has signed off in writing.
  </Step>
  <Step title="Design Phase">
    The UI/UX Designer produces wireframes, moves to high-fidelity design in Figma, and collects client approval before any development begins.
  </Step>
  <Step title="Development on Staging">
    Developers build on the staging environment only. The staging URL is shared with the client for review. Never build or make changes directly on a live site.
  </Step>
  <Step title="QA and Client Review">
    The QA team runs functional, cross-browser, and performance checks. The client then reviews on staging and submits feedback via the agreed feedback channel.
  </Step>
  <Step title="Launch and Post-Launch Check">
    Once client approval is confirmed, the PM coordinates the go-live. Run a post-launch checklist (DNS, SSL, redirects, analytics, forms) before marking the project complete.
  </Step>
  <Step title="Handover to After Sales">
    Complete the internal handover document and brief the After Sales team on the client's setup, hosting environment, and any ongoing maintenance requirements.
  </Step>
</Steps>

<Note>
  Always use a staging environment throughout the development phase. Never build, test, or apply updates directly on a live production site. Any exceptions must be approved in writing by the Project Manager.
</Note>

## Team Roles

Each web project is staffed according to scope and package type. The standard roles involved are:

| Role | Responsibility |
|---|---|
| **Project Manager** | Owns the timeline, client communication, and internal coordination |
| **UI/UX Designer** | Wireframes, Figma design, design system, client design approval |
| **Frontend Developer** | Implements design in the browser; theming, templates, responsive layout |
| **Backend Developer** | Custom functionality, integrations, APIs, database logic (Mammoth/Web Apps) |
| **QA** | Functional testing, cross-browser checks, performance audits, bug reporting |

Not all roles are active on every project type. Falcon builds, for example, typically do not require a dedicated Backend Developer unless custom integrations are in scope.
