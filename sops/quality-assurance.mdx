Quality assurance is mandatory at Hellenic Technologies before anything is delivered or launched. Every service line has its own QA checklist; use the appropriate one for your delivery type. QA is not optional, and it is not the client's job — it is yours before anything leaves the building.

<Warning>
  **Do not skip QA under timeline pressure.** It always takes more time and costs more goodwill to fix issues after launch than to catch them beforehand. If a deadline is at risk, escalate to the PM or department head — do not silently cut QA corners. Post-launch fixes often require emergency resources, client communication, and sometimes commercial compensation.
</Warning>

**General rule:** All deliverables must be reviewed and signed off by the relevant **team lead** before being shared with the client. No exceptions.

## QA Checklists by Service Type

<Tabs>
  <Tab title="Website QA">
    Run every item on this checklist before any website goes live or is shared with the client for review. Both staging and production environments must be tested.

    **Cross-Browser & Device Testing**
    - [ ] Tested in Chrome (latest)
    - [ ] Tested in Firefox (latest)
    - [ ] Tested in Safari (latest — use macOS or iOS device)
    - [ ] Tested in Microsoft Edge (latest)
    - [ ] Mobile responsiveness verified on iOS and Android (real devices or BrowserStack)
    - [ ] Tablet layout reviewed

    **Performance**
    - [ ] Core Web Vitals passing (use PageSpeed Insights or Lighthouse) — target LCP < 2.5s, CLS < 0.1, INP < 200ms
    - [ ] Images optimised and served in next-gen formats (WebP/AVIF)
    - [ ] No render-blocking resources without deferral

    **Functionality**
    - [ ] All internal and external links working (no broken links)
    - [ ] All forms submitting correctly and confirmation messages displaying
    - [ ] Form submissions reaching the correct destination (CRM, email, or database)
    - [ ] Navigation menus working correctly on all devices
    - [ ] Search functionality working (if applicable)
    - [ ] Any e-commerce flows tested end-to-end (cart, checkout, payment, confirmation)

    **Technical & Security**
    - [ ] SSL certificate active and valid (HTTPS on all pages)
    - [ ] 404 error page configured and styled
    - [ ] Redirects in place for any changed URLs
    - [ ] robots.txt and sitemap.xml present and correct
    - [ ] No staging/development URLs, credentials, or debug code in production
    - [ ] CMS admin login confirmed working with correct credentials handed over
    - [ ] Staging environment config variables separated from production (no staging APIs, keys, or endpoints in prod)

    **Content**
    - [ ] All copy proofread (no placeholder text, no typos)
    - [ ] All images loading with appropriate alt text
    - [ ] Favicons and Open Graph images in place
  </Tab>

  <Tab title="Campaign QA">
    Complete this checklist before any paid campaign goes live. A campaign that launches with errors wastes budget and can damage client trust immediately.

    **Campaign Settings**
    - [ ] Correct geographic targeting (countries, regions, cities)
    - [ ] Correct language targeting
    - [ ] Daily and total budget set correctly
    - [ ] Campaign schedule (start/end dates) confirmed with client
    - [ ] Bidding strategy aligned with campaign goals
    - [ ] Audience targeting reviewed and approved
    - [ ] Frequency caps set (where applicable — Display, Meta, Programmatic)

    **Ad Creative & Copy**
    - [ ] All ad copy proofread — no spelling or grammar errors
    - [ ] Ad copy compliant with platform policies (Google, Meta, TikTok, LinkedIn as applicable)
    - [ ] No prohibited content, misleading claims, or policy violations
    - [ ] Creative assets in correct dimensions and formats for each placement
    - [ ] Brand guidelines followed (logo, fonts, colours)
    - [ ] Headlines and descriptions within character limits

    **Tracking & Attribution**
    - [ ] Conversion tracking firing correctly — verified in platform UI and via tag testing
    - [ ] UTM parameters applied consistently to all destination URLs
    - [ ] Landing pages loading correctly and within acceptable speed thresholds
    - [ ] Landing page content matches ad messaging (relevance score / quality score implications)
    - [ ] Thank-you / confirmation page or event firing on conversion action

    **Final Pre-Launch**
    - [ ] Campaign reviewed and approved internally by team lead
    - [ ] Client has given explicit go-ahead to launch (email sign-off)
    - [ ] Launch timing confirmed (avoid launching Friday afternoon without monitoring in place)
  </Tab>

  <Tab title="Analytics QA">
    Analytics QA must be completed before any website launch, campaign go-live, or tracking configuration is handed over to the client.

    **GA4 Implementation**
    - [ ] All required events firing in **GA4 DebugView** — verify event names, parameters, and values
    - [ ] Key conversion events configured and showing in GA4 Conversions report
    - [ ] Page view tracking confirmed across all key pages
    - [ ] Enhanced measurement settings reviewed and configured appropriately
    - [ ] No duplicate events firing (check for double-firing tags)

    **Consent Mode**
    - [ ] Consent Mode v2 implemented and passing correct signals (`ad_storage`, `analytics_storage`, `ad_user_data`, `ad_personalization`)
    - [ ] Default consent state set correctly per applicable regulation (GDPR for EU clients)
    - [ ] Consent signals verified in GA4 DebugView with consent banner interactions
    - [ ] Cookie banner categorisation aligned with tag firing triggers in GTM

    **Google Tag Manager**
    - [ ] Correct GTM container published — confirm version number
    - [ ] No unpublished draft tags that should have been included in this release
    - [ ] All triggers firing on correct pages/conditions only — no over-firing on unintended pages
    - [ ] Preview mode used to verify all tag and trigger behaviour before publishing
    - [ ] GTM container access levels reviewed — only appropriate users have publish rights

    **Cross-Platform & Server-Side (if applicable)**
    - [ ] Server-side tagging container receiving hits correctly
    - [ ] Google Ads conversion import from GA4 confirmed working
    - [ ] Meta Pixel / CAPI events matching (event match quality score checked in Events Manager)
    - [ ] LinkedIn Insight Tag firing (if in scope)

    **Data Integrity**
    - [ ] Internal IP addresses filtered/excluded
    - [ ] Bot filtering enabled
    - [ ] Hostname filter in place to exclude spam referrals (if applicable)
    - [ ] Currency setting correct in GA4 property
  </Tab>

  <Tab title="Design QA">
    Run this checklist before any design deliverable — digital or print — is shared with the client.

    **Brand Compliance**
    - [ ] Brand guidelines followed throughout (logo usage, clear space, colour palette, typography)
    - [ ] Correct logo version used (colour, monochrome, reversed — as appropriate for the context)
    - [ ] No unauthorised fonts, colours, or graphic elements introduced
    - [ ] Visual style consistent with other approved brand assets

    **Digital Design**
    - [ ] Assets exported in correct formats (SVG for logos/icons, PNG/WebP for raster graphics, MP4/GIF for animation)
    - [ ] Correct resolution and dimensions for each intended placement
    - [ ] Retina/2× assets provided where required
    - [ ] Figma handoff complete — developer notes added, components named consistently, layers organised
    - [ ] Interactive states designed (hover, active, focus, disabled) for UI components

    **Print Design**
    - [ ] Files in CMYK colour mode (not RGB)
    - [ ] Resolution minimum 300 DPI at print size
    - [ ] Bleed and crop marks present per print supplier requirements (typically 3mm bleed)
    - [ ] Fonts embedded or outlined
    - [ ] Packaged file with all linked assets provided to client/printer
    - [ ] Proof approved by client before sending to print

    **General**
    - [ ] Spelling and grammar in all text elements proofread
    - [ ] Placeholder content (Lorem Ipsum, stock images) replaced with final content
    - [ ] File naming follows HT convention: `[ClientName]_[AssetType]_[Version]`
    - [ ] Final files stored in the client folder in the shared drive
  </Tab>
</Tabs>

## Escalation

If QA reveals issues that cannot be resolved within the project timeline, the PM must be informed immediately. Do not silently push a delivery date without flagging the reason. The PM will communicate with the client and agree on a revised timeline if necessary. Communicating proactively is always preferable to delivering a broken product on time.
