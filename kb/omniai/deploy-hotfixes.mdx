Normal path: **staging first, then the same files on live.** No Docker compile. Live stays up except a few seconds while Rails restarts.

Use this for Ruby, ERB, `en.yml`, Super Admin views, and a migration-only change. Same playbook lives in repo `AGENTS.md`.

<Warning>
  Do not run `deploy.sh` on these boxes. Do not `docker compose up -d` after a file copy. That **recreates** containers, boots the old image, and drops the copied files. Use **restart** only.
</Warning>

Pushing `omniai` still runs the old AWS ECS workflow. That does not update the live Droplet.

## Default path (almost every change)

<Steps>
  <Step title="Merge to omniai">
    Production branch is `omniai`. Do not leave the product PR open.
  </Step>
  <Step title="Staging first">
    Copy only the changed files to `/opt/omniai` on `164.92.220.232`. Never replace `.env` or the compose image line. `docker cp` each file into `omniai-rails-1` and `omniai-sidekiq-1` at `/app/...`.
  </Step>
  <Step title="Restart staging">
    `docker compose -f docker-compose.production.yaml -f docker-compose.staging-db.yaml restart rails sidekiq`

    Migrate only if you added a migration (same compose files, `exec -T rails bundle exec rails db:migrate`).
  </Step>
  <Step title="Check staging">
    Cloudflare Access PIN, then the app at `https://staging.omniaichatbot.com`.
  </Step>
  <Step title="Same files on live">
    Repeat the copy \+ `docker cp` on `188.166.84.105`. Then `docker compose -f docker-compose.production.yaml restart rails sidekiq`. Live stays up except a few seconds while Rails restarts.
  </Step>
</Steps>

This is how `Operator console` on Super Admin login was shipped.

## Rare path (image must change)

Only if Gemfile, native gems, Dockerfile, or compiled frontend changed.

1. Build on **staging** as `chatwoot:staging`. Leave live running.
2. From a machine that has `~/.ssh/omniai_do`, run `/opt/omniai/scripts/promote-staging-to-live.sh`. That copies the image, then does a short live recreate. `DRY_RUN=1` copies only.
3. Never compile on live. Never `docker compose down` on live to build.

File-copy hotfixes vanish on that recreate unless they are already in the new image.
