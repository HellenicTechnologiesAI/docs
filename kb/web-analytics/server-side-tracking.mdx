## Two scenarios

**Scenario A — Fix existing customer SST.** The customer already has Stape \+ web GTM \+ sGTM. Do not rebuild from scratch. Inventory first. Patch the same containers.

**Scenario B — Greenfield SST.** New domain. Build in this order: DNS Stape subdomain, Cloudflare Worker same-origin, Stape Generate, consent first, web GTM, sGTM clients and tags, pixels, QA.

Shared stack: browser hits customer.com/{path}/\* (HT: /metrics) then Cloudflare Worker (HT: ht-sgtm-same-origin, header X-From-Cdn: cf-stape) then sgtm.customer.com (DNS-only) then sGTM then GA4 / Ads / Meta CAPI / TikTok Events API / LinkedIn CAPI.

Web GTM still runs in the browser. Its library comes from the same-origin path, not Google's domain.

## Consent (how it must work)

HT uses iubenda Cookie Solution plus Google Consent Mode v2 Advanced. One CMP. Do not add Cookiebot or OneTrust on top.

Purpose map:

- 2 functionality -\> functionality\_storage
- 3 experience -\> personalization\_storage
- 4 measurement -\> analytics\_storage
- 5 marketing -\> ad\_storage, ad\_user\_data, ad\_personalization

Defaults before accept: ads trio denied, analytics\_storage denied, functionality\_storage granted, personalization\_storage denied, security\_storage granted, wait\_for\_update 2000, ads\_data\_redaction true, url\_passthrough true.

On accept: grant the mapped keys. On reject: keep denied and expire HT match / click-ID cookies.

Rules:

- consentOnContinuedBrowsing false. Do not auto-grant after the widget loads.
- When purpose 5 is granted, push once per page: `ht_consent_ready` and `gtmconsentupdate` with the same fresh event\_id.
- Seed `_ht_vid` and `_ht_fbc` from fbclid.
- Persist landing-url click IDs: ttclid, li\_fat\_id, gclid, wbraid, gbraid.
- Unblock Advanced Mode domains so hybrid pixels can load after consent: Google hosts, connect.facebook.net, TikTok analytics hosts, snap.licdn.com, px.ads.linkedin.com, first-party host, sgtm host.
- Footer is the only preferences entry (iubenda-cs-preferences-link). Hide the floating keyhole.

What fires when:

- Page load, ads denied: Custom Loader, Consent Mode defaults, pixel holds. No base Meta / TikTok / LinkedIn PageView.
- Purpose 5 granted / ht\_consent\_ready: web Meta PageView, TikTok Pixel, LinkedIn Insight base tags. GTM ads-consent on those three is notSet. Meta template consent is off. Native fbq / ttq grant.
- Later conversions: web conversion tags still require the ads trio. sGTM CAPI / Ads tags use adStorageConsent required (GCS G110 / G111 or consent\_state.ad\_storage). ED - gcs reads x-ga-gcs.
- Purpose 5 denied: no match cookies. Pixels stay held.

Stape first-touch: the landing hit must see the pixels on that same page after consent, while the URL still has fbclid / ttclid / gclid / UTMs.

Match keys (code: src/lib/analytics/meta-match.ts and meta-user-data.ts):

- `_ht_vid` 730 days = Meta external\_id / dataLayer user\_id
- `_ht_mk` 180 days = JSON of email, phone, names, geo after a form/chat/newsletter, replayed on later PageView / ViewContent
- `_ht_fbc` 90 days = built from fbclid as fb.1.ts.id

EMQ work: more quality keys (email \+ phone \+ name \+ external\_id \+ fbp \+ fbc \+ country) beat spraying empty fields. Do not send raw PII into this KB.

## QA checklist (both scenarios)

Network / HTML:

- Homepage HTML contains the exact Generate IIFE plus official GTM comments.
- Noscript matches Generate (HT: sgtm host /ns.html?id=GTM-TRPS26L, no extra title).
- No googletagmanager.com/gtm.js and no second GTM container.
- /{path}/{loader}.js?{query} returns 200 (large decoded GTM). Bare file without query is 404.
- Scripts on the page are first-party /{path}/ (loader \+ gtag). Browser must not load sgtm. as a script host. The noscript iframe is the exception.
- POST /{path}/g/collect with the GA4 tid.
- First-party FPAU / Google linker cookies appear after analytics consent.

Consent:

- Fresh browser: ads/analytics denied; no Meta PageView / TikTok / Insight.
- Accept marketing: one ht\_consent\_ready; pixels fire on that landing URL.
- Reject: _ht_\* cookies expire; pixels stay held.
- Refresh after accept does not flash the banner (HT: data-iubenda-banner=hide when \_iub\_cs- exists).

Platforms:

- GTM Preview through [https://customer.com/\{path\}](https://customer.com/{path}) (not a Next 404).
