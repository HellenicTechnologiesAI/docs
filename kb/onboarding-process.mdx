A smooth onboarding process sets the tone for the entire client relationship. This guide walks you through every step from signed contract to project kickoff — follow it without exception for every new client, regardless of project size or service type.

<Note>
  Never share Hellenic Technologies master login credentials with clients or use HT admin accounts to access client platforms. Always request that the client grants access via their own admin accounts. This protects both the client and HT in the event of any account issues.
</Note>

## Onboarding Steps

<Steps>
  <Step title="Contract Signed">
    As soon as the contract is countersigned:

    - **Account Manager** creates the client folder in the shared drive, using the standard folder structure template
    - Send the client a **welcome email** within 24 hours of signing — introduce yourself, confirm what happens next, and set expectations for the kickoff call
    - Flag the new client in the internal team Slack channel so relevant leads are aware
  </Step>
  <Step title="CRM Update">
    Add the client to the CRM immediately — do not wait until after the kickoff call:

    - Full company details (name, address, VAT, website)
    - Primary contacts (decision-maker, day-to-day contact, billing contact)
    - Services purchased (exact scope per the signed contract)
    - Contract value, billing frequency, and invoice schedule
    - Any contractual SLAs or delivery deadlines
    - Source of the lead (for reporting purposes)
  </Step>
  <Step title="Team Assignment">
    Assign the delivery team based on the services in scope:

    - Appoint a **Project Manager** — the single point of accountability for the engagement
    - Assign **specialist team members** based on services (e.g., Analytics Engineer for GA4 projects, PPC Specialist for ad campaigns, Developer for web projects)
    - Brief the team on the client background, scope, and any key context from the sales process
    - Add all team members to the client folder and project management workspace
  </Step>
  <Step title="Tool Access">
    Set up all necessary tool access before the kickoff call:

    **HT-side access to set up:**
    - Create the project in the project management tool and invite the team
    - Set up the client communication channel (email thread, shared inbox, or Slack connect)

    **Client platform access to request:**
    - Google Ads account access (if applicable)
    - Meta Business Manager access (if applicable)
    - GA4 / GTM property access (if applicable)
    - WordPress / CMS admin access (if applicable)
    - Any other relevant platform access per the scope

    Send access request emails to the client's admin contact promptly — delays here block the entire project start.
  </Step>
  <Step title="Kickoff Call">
    Schedule and run a **60-minute kickoff call** with the client within 5 business days of contract signing:

    **Agenda:**
    - Introductions (team on both sides)
    - Recap of agreed scope and deliverables
    - Goals and success metrics — what does a great outcome look like for the client?
    - Timeline walkthrough and key milestones
    - Communication preferences (frequency, channel, contacts)
    - Any immediate questions or concerns

    <Tip>
      Always record the kickoff call (with the client's permission) and share a written summary of notes and agreed actions within **24 hours**. This prevents misalignment down the line and demonstrates professionalism from day one.
    </Tip>
  </Step>
  <Step title="Discovery">
    Gather all materials needed to begin work:

    - Brand assets (logo files, brand guidelines, fonts, colours)
    - Creative assets (existing photography, videos, copy)
    - Platform logins and access confirmations (chase any outstanding requests)
    - Competitive landscape notes (if not already documented from the sales process)
    - Any existing reports, audits, or previous agency work the client can share
    - Technical documentation (for web or analytics projects)

    Assign a discovery deadline — don't let this drag. Missing assets are the most common cause of project delays.
  </Step>
  <Step title="Project Plan">
    The **Project Manager** creates the detailed project plan after the kickoff call and discovery:

    - List all deliverables with owners and due dates
    - Define milestones with clear acceptance criteria
    - Identify dependencies and flag any blockers upfront
    - Share the project plan with the client for sign-off before work begins
    - Add the plan to the project management tool so the entire team can track progress
  </Step>
  <Step title="First Delivery">
    Complete and deliver the first output within the agreed timeline:

    - The first delivery is a trust signal — prioritise it
    - Ensure it goes through the standard team lead review before being sent to the client
    - Accompany the delivery with a short context note explaining what was done and what's next
    - Log the delivery in the CRM and update the project status
  </Step>
</Steps>

## Access Request Template

When requesting client platform access, use the following format to keep things clear and professional:

```text
Subject: [Project Name] — Platform Access Request

Hi [Client Name],

To get started on [service], we'll need the following access:

1. [Platform] — please add [email@hellenictechnologies.com] as [role]
2. [Platform] — please add [email@hellenictechnologies.com] as [role]

If you have any questions about why we need these permissions, we're happy to walk you through it on a call.

Thanks,
[Your Name]
```
