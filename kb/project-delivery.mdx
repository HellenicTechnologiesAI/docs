## Milestone Protocol

Every project — regardless of size — must have a documented project plan with defined milestones.

- Create the project plan in the project management tool before work begins
- Share milestones with the client (via the PM tool or email summary) so they can track progress
- Milestone dates must be realistic and agreed with the delivery team before being shared with the client
- If any milestone is at risk of slipping, communicate to the client **at least 48 hours in advance** with a clear revised timeline and a brief explanation

<Note>
  Never over-commit on timelines to win a client or keep them happy in the short term. Under-promise and over-deliver. A missed deadline damages trust far more than a conservative initial estimate. If you're unsure how long something will take, add a buffer — and talk to your team lead before quoting a date to the client.
</Note>

## Revision Policy

All services include a defined number of revision rounds as specified in the signed contract. Make sure you know the revision entitlement before starting any deliverable.

| Scenario | Action |
|---|---|
| Revision within contracted rounds | Complete at no additional charge, within agreed turnaround |
| Request exceeds contracted rounds | Flag to Account Manager; bill at hourly rate or via retainer top-up |
| Scope change disguised as a revision | Raise a change request — do not absorb out-of-scope work silently |

Never absorb out-of-scope work without raising it with the Account Manager first. Every unbilled scope creep reduces margin and sets a bad precedent.

## Communication Standards

| Situation | Standard |
|---|---|
| Client message received | Respond within **4 business hours** (even if just to acknowledge) |
| Active project updates | Weekly status update — what was done, what's next, any blockers |
| Retainer clients | Monthly performance review call or written report |
| Issue or blocker arises | Notify the Account Manager and client immediately — don't wait for the weekly update |

Detailed communication SOPs are maintained separately per service line. Refer to the relevant SOP for channel-specific guidance.

## Quality Gates

No deliverable leaves HT without passing a quality gate. The team lead for each service line is responsible for the final review.

<Accordion title="Web Development Quality Gate">
  Before any website goes live, the following must be completed:

  - Full cross-browser QA (Chrome, Firefox, Safari, Edge)
  - Mobile responsiveness check (iOS + Android)
  - Page speed / Core Web Vitals check (Lighthouse score ≥ 85 on mobile)
  - All links tested (no broken links or 404s)
  - Forms tested end-to-end (submission → confirmation → notification)
  - GTM / GA4 tracking verified as live and firing correctly
  - SSL certificate confirmed active
  - Staging → Production deployment verified
  - Client sign-off obtained in writing before go-live
</Accordion>

<Accordion title="Digital Marketing Quality Gate">
  Before any campaign goes live, the following must be completed:

  - Campaign structure reviewed by a second team member
  - Ad copy proofread (spelling, grammar, brand voice)
  - Targeting settings verified against the brief
  - Budget and bidding settings confirmed with Account Manager
  - Tracking (UTMs, conversion tags) verified as firing
  - Landing page checked — live, fast, relevant, and conversion-optimised
  - Client approval received on ad creatives and copy
</Accordion>

<Accordion title="Analytics Quality Gate">
  Before any analytics implementation is signed off, the following must be completed:

  - All events in the measurement plan verified as firing in GA4 DebugView
  - Conversions confirmed as recording in GA4
  - Consent Mode verified — tags respect granted/denied states
  - No duplicate events or self-referral traffic
  - Cross-device and cross-browser testing completed
  - Client tracking documentation sheet completed and filed
</Accordion>

<Accordion title="Creative & Design Quality Gate">
  Before any design deliverable is sent to a client:

  - Design reviewed against brand guidelines
  - Copy proofread — no typos, correct client name/details
  - File formats correct for intended use (web, print, social, etc.)
  - Fonts embedded or outlined (for print files)
  - All linked assets included in the export package
</Accordion>
