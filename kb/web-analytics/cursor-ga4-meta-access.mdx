<Warning>
  Cursor does **not** inherit your personal Google or Meta login. Agents use one Google service account (`GOOGLE_SERVICE_ACCOUNT_JSON`) plus a Meta system user. GA4, Tag Manager, and Google Ads are **three separate products**. A grant on one never covers the others. Do not invent pixels or conversion IDs. Do not reuse HT assets on another customer.
</Warning>

Live URL: [https://ht-intra.mintlify.site/kb/web-analytics/cursor-ga4-meta-access](https://ht-intra.mintlify.site/kb/web-analytics/cursor-ga4-meta-access).

## What you are granting

| Surface | Who Cursor is | One grant covers |
| --- | --- | --- |
| **GA4** | Same `client_email` | **One add per Analytics Account.** All current and future properties under that account. |
| **Tag Manager** | Same `client_email` | **One add per GTM Account** as Account Admin. All current and future containers under that account. |
| **Google Ads** | Same `client_email` on the **MCC** | **One add on the manager account.** Every client account already linked under that MCC, plus new links you accept later. |
| **Meta** | `HT-SysAdmin` or system user **HT Cursor** | All ad accounts and datasets in the HT portfolio, plus assets clients Partner-share into HT. |

Google Cloud IAM on the GCP project is **not** enough. You must add the email inside each product UI (or API).

Enable these APIs on the **same** GCP project that owns the service account: Analytics Admin API, Tag Manager API, Google Ads API.

## Find the service account email

1. Cursor **Cloud Agents → Secrets** → `GOOGLE_SERVICE_ACCOUNT_JSON`.
2. Copy `client_email` only (`…@….iam.gserviceaccount.com`). Never paste the private key into chat, Git, or this KB.

If the secret is missing, stop and add it. Do not create a second service account unless the old JSON is lost.

## GA4 — Account, not Property

<Warning>
  The GA4 **Add users** box turns `cursor@hellenicai.iam.gserviceaccount.com` red and says it is not a Google Account. That is a UI bug. The email is valid. Close the dialog. Add the service account with the Admin API below. Do not create a second service account and do not switch to a `@gmail.com`.
</Warning>

Property-level share is why Cursor only sees HT `properties/394561578`. Stop doing that.

<Steps>
  <Step title="Open Account Access Management">
    [analytics.google.com](https://analytics.google.com/) → **Admin** → **Account** column (not Property) → **Account access management**. You need Administrator on that account.
  </Step>
  <Step title="Add the service account">
    **\+** → **Add users**. Paste `client_email`. Uncheck notify. Role: **Editor** (key events, audiences). **Administrator** only if agents must invite other users.
  </Step>
  <Step title="Once per Analytics Account">
    Repeat for every GA4 **account** you admin. New properties under those accounts inherit the grant.
  </Step>
</Steps>

### UI is red — add it in OAuth Playground (2 minutes)

Use the Google account that is already **Administrator** on goldengastro.de (or the parent Analytics account).

1. Open [Google OAuth 2.0 Playground](https://developers.google.com/oauthplayground/).
2. Gear (top right) → leave defaults (or tick **Use your own OAuth credentials** if you have a Desktop client). Close the gear.
3. Left list: paste this scope only, then **Authorize APIs**: `https://www.googleapis.com/auth/analytics.manage.users`
4. Sign in. **Allow**. **Exchange authorization code for tokens**.
5. **Step 3** → HTTP method **POST** → this URL (account-level, preferred). Get **Account ID** from GA4 Admin → Account settings (digits only): `https://analyticsadmin.googleapis.com/v1beta/accounts/ACCOUNT_ID/accessBindings`
6. Request body:

```json
{
  "user": "cursor@hellenicai.iam.gserviceaccount.com",
  "roles": ["predefinedRoles/editor"]
}
```

7. **Send the request**. A `200` with a `name` like `accounts/…/accessBindings/…` means it worked. Reload GA4 User Management — the service account appears even though the form still refuses to type it.

If you only have Admin on the **property** (not the account), POST to `https://analyticsadmin.googleapis.com/v1beta/properties/PROPERTY_ID/accessBindings` instead. Property ID is Admin → Property settings (digits, e.g. HT is `394561578`). Account-level is better so you do not repeat this for every site.

Same pattern for GTM if that UI also rejects the email: POST `https://tagmanager.googleapis.com/tagmanager/v2/accounts/ACCOUNT_ID/user_permissions` with scope `https://www.googleapis.com/auth/tagmanager.manage.users` and body `{"emailAddress":"cursor@hellenicai.iam.gserviceaccount.com","accountAccess":{"permission":"admin"}}`.

If the UI rejects `*.iam.gserviceaccount.com` and you prefer terminal, use the Admin API. Run this **as yourself** (OAuth), scope `https://www.googleapis.com/auth/analytics.manage.users`.

```bash
export SA_EMAIL="paste-client-email-here"

curl -sS -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://analyticsadmin.googleapis.com/v1beta/accounts"

# Then once per ACCOUNT_ID:
curl -sS -X POST \
  "https://analyticsadmin.googleapis.com/v1beta/accounts/${ACCOUNT_ID}/accessBindings" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d "{\"user\": \"${SA_EMAIL}\", \"roles\": [\"predefinedRoles/editor\"]}"
```

Client-owned GA4 accounts you do not admin stay invisible until that client adds the same email at **their** account level. Golden Gastro `G-LNPZX5HKQF` is in that bucket until its account includes the SA.

## Tag Manager — Account User Management, not one container

GTM is not GA4. Publishing HT web `GTM-TRPS26L` does **not** grant `GTM-N8ZFXBTK` or any other container.

<Steps>
  <Step title="Open Account User Management">
    [tagmanager.google.com](https://tagmanager.google.com/) → pick the **account** in the left list → **Admin** → **Account** column → **User Management**. Not Container User Management.
  </Step>
  <Step title="Add Account Admin">
    **\+** → **Add users**. Paste `client_email`. Account permission: **Admin**. That covers every container in the account, including ones created later. Do not add the SA on a single container (Read / Edit / Publish) unless this is a client-owned account they will not promote to Admin.
  </Step>
  <Step title="Once per GTM Account">
    HT web (`1226191120`) and HT SST (`6202173174`) are two accounts. Customer web containers often live in more accounts. Add the same email to each account you admin.
  </Step>
</Steps>

If the UI rejects the service-account email, use the Tag Manager API as yourself. Scope: `https://www.googleapis.com/auth/tagmanager.manage.users`.

```bash
export SA_EMAIL="paste-client-email-here"

curl -sS -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://tagmanager.googleapis.com/tagmanager/v2/accounts"

# Then once per GTM ACCOUNT_ID:
curl -sS -X POST \
  "https://tagmanager.googleapis.com/tagmanager/v2/accounts/${ACCOUNT_ID}/user_permissions" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d "{\"emailAddress\": \"${SA_EMAIL}\", \"accountAccess\": {\"permission\": \"admin\"}}"
```

Client-owned GTM accounts (Golden Gastro `GTM-N8ZFXBTK` if it is not under an HT account) need the client, or you as their Admin, to add the same email on **that** account.

## Google Ads — one MCC, then link every client

Do not invite the service account on each advertiser account. Put every HT-managed Ads account under **one manager account (MCC)**, then add the SA once there.

<Steps>
  <Step title="Confirm the MCC">
    [ads.google.com](https://ads.google.com/) → switch to the **manager** account (not HT advertiser `736-760-0503` unless that _is_ the MCC). **Accounts** should list every client you run. If a client is missing, **Accounts → Link existing accounts** (or send a manager-link request) and wait for accept.
  </Step>
  <Step title="Add the service account on the MCC">
    Still on the MCC: **Admin → Access and security → Users → \+**. Paste `client_email`. Access: **Standard** (enough to read conversions, upload offline conversions, and inspect conversion actions). Google often blocks **Admin** on service accounts. New client accounts you link later inherit this user.
  </Step>
  <Step title="API secrets">
    MCC **Tools → API Center**: copy the **developer token**. Store in Cloud Agent secrets as `GOOGLE_ADS_DEVELOPER_TOKEN` and `GOOGLE_ADS_LOGIN_CUSTOMER_ID` (MCC ID, digits only, no dashes). Reuse `GOOGLE_SERVICE_ACCOUNT_JSON`. Enable **Google Ads API** on the GCP project. API calls must send `login-customer-id: MCC_ID`.
  </Step>
</Steps>

Accounts that are **not** linked under that MCC stay invisible, even if you can open them in the UI with your personal login. Same rule as Meta Partner shares.

Included in Conversions is still UI-only. Agents can list and create conversion actions; a human may still need to flip that toggle.

## Meta — portfolio Full control, then Partner for client BMs

`HT-SysAdmin` seeing no Golden Gastro pixel is expected if that dataset lives in the **client** Business or was never assigned inside HT.

### A. Assets HT already owns (once)

<Steps>
  <Step title="Prefer a system user">
    [business.facebook.com](https://business.facebook.com/) → **Settings → Users → System users** → add **HT Cursor** (Admin). Keep `HT-SysAdmin` as the human fallback.
  </Step>
  <Step title="Full control + assign all assets">
    Give HT Cursor / `HT-SysAdmin` **Full control** of the HT portfolio. **Assign assets**: select all **Ad accounts** and all **Datasets**. Optional: one **Business asset group** named `HT tracking`, assign the system user to the group.
  </Step>
  <Step title="Token">
    Generate a token with `ads_management`, `ads_read`, `business_management`. Store as `META_SYSTEM_USER_TOKEN`. Adding assets later does not need a new token.
  </Step>
</Steps>

Do **not** create a new pixel because the API 404s. Do **not** point a customer tag at the HT pixel.

### B. Client-owned Businesses

1. Client BM → **Partners** → add the **HT Business ID**.
2. Share the ad account \+ dataset (Advertise \+ Manage dataset).
3. Accept in HT, then **Assign assets** to HT Cursor.

One Partner accept per client Business. There is no Meta dump of every BM your personal login can open.

## What Cursor still must not do

- Treat GTM access as GA4 or Ads access.
- Create a Meta pixel or Ads account because an API 404s. Pause the tag and report **not writable**.
- Reuse HT pixel, HT GA4 `G-GYMSRM45JV`, HT web `GTM-TRPS26L`, or HT Ads `736-760-0503` on another hostname.
- Store tokens in Git, Mintlify, or a customer prompt.

## Check it worked

Ask a Cloud Agent (read-only):

1. **GA4** — list accounts/properties. More than `properties/394561578`.
2. **GTM** — list accounts/containers. Must include customer web containers, not only `GTM-TRPS26L` / `GTM-WKJ6FDLB`.
3. **Ads** — `ListAccessibleCustomers` with `login-customer-id` = MCC. Must list linked client accounts, not only HT `736-760-0503`.
4. **Meta** — list ad accounts and datasets. Golden Gastro appears only after the Partner share.
5. Then resume the customer job against **that** property, container, Ads account, and pixel.
